# Content and Structure Contracts: Humanoid Robotics Book Project

**Date**: 2025-12-06
**Feature**: `001-humanoid-robotics-book`
**Spec**: `specs/001-humanoid-robotics-book/spec.md`

## Overview

This document outlines the contracts governing the content structure and authoring within the Docusaurus-based Humanoid Robotics book project. Since Docusaurus is a static site generator, traditional API contracts (like REST/GraphQL schemas) are not applicable in the same way. Instead, the "contracts" refer to the agreed-upon formats and structures for content files and navigation configuration, ensuring compatibility with Docusaurus's rendering and build processes.

## Contracts

### 1. Markdown/MDX Content File Contract

*   **Description**: All book chapters and documentation pages will be authored using Markdown or MDX (Markdown with JSX) syntax. Each content file must adhere to Docusaurus's expected format for processing.
*   **File Naming**:
    *   Files should use `.md` or `.mdx` extensions.
    *   Filenames should be descriptive and URL-friendly (e.g., `introduction.md`, `chapter-ros-fundamentals.md`).
*   **Front Matter (YAML)**: Each Markdown/MDX file **MUST** begin with YAML front matter enclosed by `---`, providing essential metadata.
    *   **Required Fields**:
        *   `title`: The display title of the page/chapter. (e.g., `title: Introduction to Humanoid Robotics`)
        *   `id`: A unique identifier for the document, often derived from the filename. (e.g., `id: introduction`)
        *   `sidebar_label`: The label to display in the sidebar navigation. (e.g., `sidebar_label: Introduction`)
    *   **Optional Fields**:
        *   `slug`: Custom URL path for the document (if different from default).
        *   `tags`: Keywords for categorization or search.
        *   `description`: A brief description for SEO or social media previews.
        *   `authors`: List of authors for a specific document.
        *   `keywords`: Specific keywords for SEO.
*   **Content Body**:
    *   Follow standard Markdown/MDX syntax for headings, paragraphs, lists, code blocks, and other formatting.
    *   Images: Use relative paths for images stored within the `static/` directory or `docs/assets/` to ensure portability. External image URLs are also supported.
    *   Code Blocks: Use fenced code blocks with language specifiers for syntax highlighting.
    *   Admonitions (Notes, Warnings, Tips): Utilize Docusaurus's built-in admonition components.
*   **Version Control**: All content files are expected to be managed under Git for version control, collaboration, and history tracking.

### 2. Sidebar Navigation Configuration Contract (`sidebars.js`)

*   **Description**: The `sidebars.js` file defines the hierarchical structure of the book's navigation sidebar. This contract ensures that all chapters and sections are correctly organized and discoverable.
*   **Format**: The file **MUST** export an object where keys represent sidebar IDs and values define the structure using Docusaurus's sidebar items.
*   **Item Types**:
    *   `type: 'doc'`: Links to a specific Markdown/MDX document (via its `id`).
    *   `type: 'category'`: Creates a collapsible section in the sidebar.
        *   `label`: Display name for the category.
        *   `items`: Array of nested sidebar items (docs, categories, links).
        *   `collapsed`: Boolean, whether the category is collapsed by default.
    *   `type: 'link'`: Links to an external URL.
*   **Ordering**: The order of items within `sidebars.js` directly dictates their appearance in the sidebar. Manual ordering or `autogenerated` categories can be used.
*   **Consistency**: The `id`s referenced in `sidebars.js` **MUST** match the `id`s specified in the Markdown/MDX front matter.

### 3. Docusaurus Configuration Contract (`docusaurus.config.js`)

*   **Description**: This file (`docusaurus.config.js`) defines the global configuration for the Docusaurus site, including title, tagline, favicon, plugins, themes, and Navbar settings.
*   **Required Configuration**:
    *   `title`: Global site title.
    *   `tagline`: Site tagline (optional but recommended).
    *   `favicon`: Path to the site's favicon.
    *   `url`: Base URL for the deployment.
    *   `baseUrl`: Base URL for the site path.
    *   `projectName`, `organizationName`: For GitHub Pages deployment.
    *   `presets`: Configuration for themes and plugins.
    *   `themeConfig`: Configuration for the active theme, including Navbar and Footer.
*   **Customization**: Custom plugins or themes will be configured here.

## Interface Specifications

*   **CLI Interface (for Authors)**: Authors will interact with the Docusaurus CLI for local development, building, and serving the site.
    *   `npm start` or `yarn start`: Starts a local development server.
    *   `npm build` or `yarn build`: Builds the static site for deployment.
    *   `npm deploy` or `yarn deploy`: (If configured) Deploys the built site.

*   **Web Interface (for Readers)**: The deployed Docusaurus site provides the user interface for readers, featuring:
    *   **Navbar**: Global navigation, search bar, links.
    *   **Sidebar**: Hierarchical chapter navigation.
    *   **Content Area**: Markdown/MDX rendered content.
    *   **Search**: Full-text search functionality.
    *   **Footer**: Copyright, links.
